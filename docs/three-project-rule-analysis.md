## 差异来源和新增规则

原34条规则全部保留。新增71条 `LEARN-项目编号-序号` 规则，按人工分组逐条记录来源、条件、原因、优先级、覆盖关系和项目范围；其中第一组24条、第二组27条、第三组20条。优先级40，只有明确声明覆盖的旧原因规则才可被取代。

- **项目前缀缺失**：三组中Z、ZD按人工表归为二极管，TVS为瞬态抑制器，M为IC。只在这些项目中映射，不改变其他项目的类型判断。
- **后缀与SG原因缺失**：按人工表补齐对应项目的SG、TVS、U后缀及原因；SG不是由“短路检测列Х”推算得到。
- **同类不同值的分类差异**：电容pF/nF/uF及电阻的显示标准值和原因由对应项目人工表校准。匹配使用原始标准值文本，输出可使用已核对的显示文本。
- **具体电路关系**：CD3/47uf与135uf并联、CD1/330uf、R484与1k并联等只应用于对应项目、位号和原始标准值。不能从三组样例推出通用的物理判定公式。
- **相同值、不同原因**：按后缀和已验证位号集合缩小匹配范围，避免同一项目内的不同电路错误合并。

每条规则的完整条件在 `config/rules.json`。`references` 为限定的位号集合，`displayValue` 为校准后的显示标准值，`inspections` 为适用检测项目，`profile` 为项目边界。规则界面可编辑这些字段，删除采用停用归档，可恢复；规则来源原文和修改历史继续保存。

## 验证范围和待确认边界

三组用户提供的缺件Х记录已逐一与人工表匹配标准值和原因，生成文件回读检查位号总数、分组数量与来源对应关系。三份正式回归输出保存在本机 `outputs/v0.4.0-三组回归/`，不覆盖用户原文件。

已验证的是这三组项目的**缺件**原因。71条新规则默认只用于缺件；短路、错件、空焊没有对应人工原因样表，不能自动沿用缺件原因。用户可在软件中分别校准并保存为新规则。

10%/30%仍无自动公式，D/Q/IC仍只读取Coverage的√/Х/∕。其他项目或未覆盖的条件继续提示选择原因。新增规则是已核对项目的经验归因，不声称验证了每块板的物理电路根因。

公开仓库包含规则及文件哈希证据，不新增分发这三组用户原始报告。外部样例测试在本机通过；公开源码缺少本机样例清单时明确跳过该项，其他回归仍可独立运行。
