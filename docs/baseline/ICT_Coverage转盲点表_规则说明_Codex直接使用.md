## 3. 规则冲突与判定边界

1. **读取并定位字段**：解析文件类型、模板、ICT缺件列，校验表头。数据缺失则终止并提示。
2. **筛选不可测**：只用ICT缺件标志Х等。其他状态不混入盲点。
3. **提取元件信息**：位号清理、识别前缀、保留E列标准值。未知位号进入审核。
4. **检查分类冲突**：不同来源规则可能对同一元件产生不同判断。冲突时人工审核，不要只靠顺序覆盖。
5. **项目专属例外**：如10.00pF、C115；仅当前项目启用。其他项目默认关闭。
6. **R/B优先标记**：/PCB→/NP；/R需额外可测性信息。10%不得直接作为已判定结果。
7. **C优先标记**：/PCB、SG、/NP、/C；遇混合标记单独检查。30%不自动算。
8. **其他类型**：L/D/Q/U/J/P/F/X/Y默认归类。D/Q/U原因需测试程序确认。
9. **未知分类处理**：显示原值、匹配规则和源行号。用户确认前禁止无声丢失。
10. **分组统计**：（标准值显示、原因代码）分组。组内数字与位号数一致。
11. **导出检查**：源不可测数=盲点数合计=输出实际清单数。核验后导出。

## 7. 请 Codex 执行

请将以上规则写入项目的`docs/coverage-to-blindpoint-rules.md`，按规则ID建立可配置的`rules.json`（区分已启用/仅供审核/项目特例），并根据源报告、目标盲点表、《零件测试规则.xlsx》进行自动化回归测试。

**必须先满足以下硬性要求：**

1. 从Coverage的**ICT→缺件**列筛选，不依靠位号后缀决定是否可测。
2. 自动分类必须记录命中的ruleId、原始行号、原始位号、处理后位号、原始标准值与输出原因。
3. 先复现当前样例的 1202 / 1000 / 202 / 99，核对 `C246`、`RA4`、`P21001`。
4. `/R`的10%、`/C`的30%、`SG`及D/Q/IC程序判定：**没有充分输入就标记待审核**；不要仅凭现有规则自行计算可测性。
5. 输出Excel保持原盲点表格式；源不可测数、输出位号条数、盲点数量合计必须一致。
6. 新项目应用时项目专属规则默认关闭；原文有歧义的规则需要手工确认后启用。

本文件是**规则需求记录**，不是声称已能独立计算所有元件是否可测的测试算法。
