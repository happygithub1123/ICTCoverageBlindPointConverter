# ICT 盲点表工具 · WHAPPY v0.3.2

**设计人员：王开心 · WANG KAIXIN**
**Designed by WHAPPY**

[下载 Windows x64 运行包](https://github.com/happygithub1123/ICTCoverageBlindPointConverter/releases/latest) · [当前版本说明](docs/RELEASE-v0.3.2.md)

本地运行的 C# WinForms 软件，将已经确认的 Coverage 报告整理成 ICT 盲点表。

## 运行

解压整个运行包，双击 `ICT盲点表工具.exe`。支持 Windows x64，自带 .NET 运行环境，无须安装 Microsoft Office 或 .NET SDK。请保留同目录 DLL 和 config，不要只复制 EXE。

## 主要操作

1. 点击“导入报告”，选择 `.xls` 或 `.xlsx`，自动读取分析。也可拖入报告。
2. 在“分类筛选 / 复制”中选择电阻、电容、电感、二极管等，查看按标准值和原因形成的分组。
3. “复制本组位号”用于一个单元格；“复制本组四列”从 Excel B 列起粘贴位号、数量、标准值、原因。位号为 `R103.R104.`，保留末尾英文句点和换行。
4. 未明确的原因在“异常 / 待确认”中选择，填写修改人和选择说明。无需重复确认可测性或提交测试程序。
5. 点击“导出盲点表”选择保存位置。每次**只生成一个盲点表.xlsx**，不会附带核对报告或日志文件。

内置模板固定使用示例格式，自动保持标题、Logo、列宽、边框、备注及签字区。项目编号、统计和明细由当前报告覆盖。导出后可打开文件或所在目录。

“输出设置”默认折叠，可修改项目编号、值针率、备注和位号换行宽度。默认备注留空沿用模板，值针率不填写则显示“未提供”。

## 检测规则

- **X/Х/×/✕：不可测，纳入盲点表。**
- **√/✓/✔：可测，排除。**
- **∕/／：无此不良现象，排除。**
- 黄色底纹和NP只作为原始信息，不改变以上结果。

软件只整理已经确认的检测结果并匹配盲点原因。10%、30%不自动生成判断公式，D/Q/IC不再要求测试程序证据；没有匹配原因时由用户选择。未知检测符号和重复位号等数据问题仍会提示，避免无声遗漏。

样例为1202条、1000个盲点、202个可测、99组；新流程没有原先的72条重复确认。Q7_2_3/NP的缺件列为√，直接排除。以上数字仅为样例回归预期，不是产品固定值。

## 规则管理

“规则设置”支持表单新增、编辑、删除和恢复分类规则，可设置类型、前缀、后缀、标准值、指定元件、原因、优先级、项目范围及来源。原因下拉框可输入新原因。数值小的优先级先匹配；不同原因发生未定义冲突时进入原因选择。“覆盖规则编号”可明确声明覆盖关系。

规则删除后停用归档，勾选“显示已删除规则”即可恢复。核心管线只读，可在“V2规则总览”查看。规则及原因选择记录在软件内的“人工修改日志”查看，不额外导出附件。

项目规则默认自动识别，也可在规则设置中选择通用模式关闭项目特例。规则保存后重新分析，之前选择不会静默套用到新的规则。

运行配置位于 `%LOCALAPPDATA%\ICTCoverageBlindPointConverter\rules-v3.json`。首次迁移已有V2配置，原文件保留。人工选择按源文件、规则和项目保存到同目录的会话文件，重复读取时可以恢复。

## 开发与发布

源码需要 .NET 8 SDK。运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
powershell -ExecutionPolicy Bypass -File .\publish.ps1 -Version 0.3.2
```

源码中的 samples 用于回归测试，运行包不依赖它。原始规则台账和历史差异在 docs 中保留；当前行为以v0.3.0说明及用户最新确认的符号规则为准。

## v0.3.1 更新

D/Q/IC与其他元件统一使用报告符号筛选，不查看程序。规则总览分别显示“当前执行”和“历史依据”，旧程序字段只保留兼容和追溯用途，不参与校验或拦截。默认运行规则版本2.1.1，原有自定义规则及其版本保留。每次仍只生成一个盲点表.xlsx。

## v0.3.2 文件占用修复

Coverage在Excel/WPS中打开时，可读取其已保存内容。导入期间使用同一份只读副本，不修改源文件；会话指纹不再反复读取原文件。若程序对文件使用完全独占锁，请保存并关闭该报告后重试。未保存的编辑内容需要先保存，再点击“读取分析”。
